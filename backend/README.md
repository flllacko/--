# FastAPI 后端

当前工程已经完成 P4 基础工程、P5 公共知识库处理引擎、P6 RAG 问答闭环、P7 账号/历史会话和 P8 公共资料管理后台。当前已提供检索、固定结构回答、来源绑定、证据不足拒答、流式输出、注册登录、访客临时会话、登录用户历史保存、管理员资料上传/队列/重试/删除和用户密码重置；私人知识库真实处理属于 P11。

- `GET /api/health`：检查服务是否启动，并返回当前模型配置。
- `app/db/schema.sql`：SQLite 最小业务结构。
- `app/db/init_db.py`：负责初始化 SQLite 业务表。
- `app/processing/`：P5 公共资料处理模块，负责 Markdown/网页正文/PDF/DOCX/Excel 提取、清洗、切片、Ollama 向量化、SQLite 状态记录和 LanceDB 检索副本写入。
- `runtime-data/sqlite/app.db`：运行时业务状态，不修改项目原始 `data` 文件。
- `runtime-data/index`：LanceDB 检索副本，可以由 SQLite 和资料正文重新构建。

当前 P5-S01～P5-S08 已完成：真实批处理 752 份正文，SQLite 记录 3,642 个切片，LanceDB 写入 3,642 个向量行；加入 P6～P8 测试后，后端当前标准库 `unittest` 总数为 60/60。P6-S01～S06 已提供检索、固定结构回答、来源绑定、拒答、流式输出和停止边界；P6-S06 已用 138 条自然问法完成答案级回归：131 条完成、7 条按证据门槛拒答、0 条请求错误。P7 新增账号、密码哈希、服务端会话和历史会话接口；登录用户的完整回答才保存，访客回答只保留在当前标签页。P8 新增管理员公共资料上传、单 worker 处理队列、失败重试、排队取消、批量时效、原文件下载、二次确认删除和操作记录。Ollama 回答调用显式设置 `num_ctx=8192`、`num_predict=512` 和 JSON 格式，避免证据较多时输出被默认上下文截断；解析异常只允许受控重试，不无限调用模型。SQLite 是业务状态真源，LanceDB 只作为可重建的检索副本。
